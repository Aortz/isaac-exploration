Field test brief · drone simulation

Sim Fidelity Field Kit

What to bring back from field tests so our Isaac Sim / Pegasus models fly like the real aircraft, and so every simulated test can be checked against a real one. Written for the Spirit coaxial program; most of it applies to any airframe.

MUST blocks a calibrated model SHOULD big accuracy gain NICE when time allows

If you only have one field day

  1. Export the full ArduPilot parameter file and note the firmware version.
  2. Weigh the aircraft in the configuration you fly, and record the payload and battery setup.
  3. One flight log with logging set as below: 60 s hover, then the System ID manoeuvres, then a few forward-flight speed steps.
  4. Camera intrinsics, camera–IMU extrinsics and time offset from Kalibr, plus a 2-hour static IMU log.
  5. One ROS 2 bag of the nominal loop (profile P3) with RTK ground truth and a wind reading.
01 · once per airframe

Vehicle configuration

Today the coaxial model runs on estimates: 4.0 kg, inertia (0.06, 0.06, 0.025) kg·m², ±10° swashplate, 0.15 m hub height. Real values replace every one of them.

Feeds pegasus.vehicles.coax_spirit in config/flight.yaml and ardupilot/params/coax_spirit.parm.

02 · bench

Propulsion test stand

Thrust, torque and spin-up time are what the flight controller fights against. The coaxial model needs the upper/lower rotor split, which only a bench run of the pair together shows.

Feeds thrust_coeff, torque_coeff, lower_rotor_efficiency, max_rotor_speed_rad_s, motor_tau_s.

03 · every flight

Flight logs and System ID

Logs let us fit the model to the real response and compare simulated and real flights axis by axis. System ID manoeuvres are the fastest way to get clean data for that.

Feeds the vehicle model fit, rate-loop checks, drag coefficients and the IMU vibration model.

04 · once per sensor rig

Camera and IMU calibration

The simulated rig is exact by construction. VIO results only transfer to the real aircraft if lens models, mounting and timing in sim match the real rig.

Feeds rig and stereo in config/flight.yaml, the imu noise block, and the OpenVINS config.

05 · test-plan flights

Ground-truthed datasets

The direct sim-to-real check: the same profiles we fly in sim, flown for real with ground truth, run through OpenVINS and MAC-VO with the same scoring.

Feeds testplan/ scoring and docs/test_plans.md profiles P1–P7.

06 · every field day

Site, wind and conditions

The wind model takes a mean, a turbulence level and gusts. A capture of the site lets us rebuild it as a NuRec scene and fly the same place in sim.

Feeds wind: blocks in flight configs and new environments entries.

07 · handoff

Per-flight record and folder layout

Data we cannot match to a configuration is data we cannot use. One row per flight in a shared sheet, one folder per flight.
